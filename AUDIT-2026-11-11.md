# Audit record, 11 November 2026

An independent read-only audit of the package and its tests was run on commit 0c1764c.

## Checked and found sound

- The Olofsson et al. (2014) formulas are implemented correctly: the proportions, the cell, overall, user's and producer's accuracy variances, and the sample size formula. Running the paper's Table 8 example gives overall accuracy 0.9465 plus or minus 0.0185, deforestation area 21,157.8 plus or minus 6,157.5 ha, user's accuracy 0.880 plus or minus 0.074 and producer's accuracy 0.749 plus or minus 0.213. These match the published example as far as the auditor recalled it; they were not re-checked against the paper in the audit.
- `SpatialBlockKFold` never puts a block in both training and test sets.

## Findings and corrections

| Finding | Status |
| :--- | :--- |
| The test suite failed at collection: the tests imported `kling_gupta_efficiency`, `nash_sutcliffe_efficiency`, `percent_bias` and `rmse`, which do not exist, so no test ran | The hydrological test now skips until a `metrics` module exists; 2 tests pass and 1 skips |
| The README, the package description and the docstring promised hydrological skill metrics and Monte Carlo sensitivity auditing, which are not in the package | All three now say they are planned and not implemented |
| The block cross-validation has no buffer: with 10 km blocks the minimum train-to-test distance was 214 m, so neighbours across block edges leak into training. The test only asserts that the distance is greater than zero | Documented in the README |
| `olofsson_area_estimate` warns about an invalid divide when a reference class has zero estimated area, and `allocate_stratified_sample` can return 718 samples when the formula gives 641 because of the minimum per class | Documented in the README |
| Moran's I, variograms and kriging are not in the package although the name suggests spatial statistics | Open |

## Open

- Implementing the metrics module and the Monte Carlo auditing is new work and was not done.
- A buffer or a block size tied to an estimated autocorrelation range would bring the cross-validation closer to the recommendation it cites (Roberts et al., 2017).
- `groundwater-storage-gravimetry` lists this package as a dependency, and nothing in it imports the package.
